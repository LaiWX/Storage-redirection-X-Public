# 仅监控权限边界修复（patch.2）

引入修改后，对于仅监控的应用，将正常按 Android 原有权限访问存储。

## 问题描述

修改前，仅开启监控也会使应用的存储访问进入代理路径，导致应用获得超出 Android 原有权限与目录隔离范围的文件访问能力。

## 根因

修改前，未配置应用的存储根被交给共享宿主或 scoped FUSE。仅监控策略把请求路由到真实后端；宿主以自身身份打开 `/data/media/<user>`，导致绕过请求者的 MediaProvider 权限、目录隔离和脱敏语义。

## 修改

将仅监控从存储代理流程中分离，改用应用 Monitor hook 和系统侧 inotify 观察。启动时不再为仅监控生成挂载请求；reconcile 将仅监控请求改为 `Disable`，无已有挂载状态时跳过，有已有挂载状态时仅执行清理。

companion 的挂载准入条件排除仅监控请求；共享宿主预挂接、策略登记、FUSE 根规划及会话构造也在执行前检查仅监控标记，避免其他调用路径为其建立代理。普通应用的 Monitor hook 直接调用原始操作。

## 预期效果

仅监控不再建立新的存储挂载、登记共享宿主策略或构造代理会话；reconcile 对已有挂载只执行停用清理。文件操作继续经过 Android 原有存储视图与权限检查。Monitor hook 保留原始操作的成功或失败结果及 errno。

## SQLite 兼容例外的授权边界

MediaProvider 的 SQLite 兼容例外仅适用于明确启用重定向的目标配置，监控开关和路径 token 不构成授权。
