# 文件监视改善（patch.3）

## 文件监视记录黑名单

文件监视的过滤入口改为“黑名单规则”，规则仅控制生效后的日志写入，历史记录不受影响。删除规则后恢复后续记录。

## 黑名单过滤判定修复

修复源头路径判定：规范化共享存储别名后，按用户存储根下的相对路径匹配黑名单。

## 文件监视日志职责与存储重构

去重、请求与观察关联、FUSE 创建与写入合并、中间记录清理统一由 daemon 处理。优先通过 `correlation_id` 关联；无关联 ID 时，仅合并同用户、同应用、同路径、操作与结果兼容且时间差不超过 1500 ms 的唯一匹配。独立重复操作和存在歧义的事件分别保留。

`file_monitor.log` 改为最多保留最新 1000 条最终记录，取消容量轮转和数字备份。移除累计 64 行触发 flush 的条件，每 2 秒通过临时文件原子保存有变化的日志。保存失败时保留旧文件和待保存状态，下一周期重试；手动清空完成保存后才确认成功。

首次启用新存储格式时，清空旧主日志及数字备份。后续重启加载已保存的最终记录。

App 直接读取主文件全部内容，移除备份拼接、条数截取以及消费端的合并和清理。导出记录通过 `daemon monitor-record` 命令进入统一处理流程。

修复刷新与清空的并发竞争：旧刷新及应用信息查询不能覆盖新状态，避免清空后旧日志重新出现。

## 日志条目显示

非本日条目增加日期：同年显示月日和时间，跨年显示完整日期和时间。日期判断随设备本地日期更新，支持前台恢复、跨午夜以及系统时间或时区变化。

缩减时间与展开按钮之间的留白，并将点击区域移到按钮外层。空间不足时，时间与按钮整体移至下一行，避免日期挤占应用名称。
