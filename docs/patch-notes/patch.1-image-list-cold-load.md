# 图片列表冷加载优化（patch.1）

引入修改后，冷加载图片列表的等待时间可缩短；并维持列表内容按重定向与隔离的行为。

## 问题描述

对于已隔离的应用，冷加载图片列表时需要消耗时间超出预期。

## 根因

查询结果中的原始路径和重写路径逐行调用 `faccessat` 检查是否存在。同一目录内的文件分别触发系统调用，未复用目录条目信息。

## 修改

为单次 Cursor 过滤建立存在性检查作用域，按需扫描父目录，通过 `getdents64` 收集普通文件名。同一次过滤中命中的条目直接复用快照结果。Java `finally` 确保正常返回或异常时均结束作用域，嵌套查询使用独立作用域。

## 预期效果

同一次 Cursor 过滤中，同一父目录的快照只构建一次，命中的普通文件条目不再逐个调用 `faccessat`，从而减少系统调用次数与过滤开销。路径重写与隔离规则仍逐行执行，快照在过滤结束后释放，不跨查询复用；未命中或不满足快照条件时执行原有存在性检查。

## 适用边界与回退行为

快照仅用于 64 位 Android/Linux 的 ext4、F2FS 目录，并要求线程非 root、各 UID/GID 身份分别一致、无有效 capabilities，且父目录通过搜索权限检查。未命中、符号链接、未知文件类型、扫描失败或不支持的情况均回退到原有系统调用，不将快照缺失视为文件不存在。单条 URI 查询跳过快照；每个作用域最多缓存 128 个目录、65,536 个条目，按预算计费限制为 16 MiB，超限时回退。

## 构建兼容性调整

此次修改同时补充对带小版本后缀的 Android SDK 平台目录的识别，并为本地构建脚本显式指定 Android arm64 链接器。
